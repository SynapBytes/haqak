# Advanced Features Documentation - صوتك

## نظرة عامة على التحسينات المتقدمة

تم تطوير مجموعة شاملة من الميزات المتقدمة لضمان أن منصة "صوتك" توفر تجربة احترافية وآمنة وفعالة للمواطنين والنواب والإدارة.

---

## 1. نظام تتبع الشكاوى عبر SMS (SMS Tracking System)

### الهدف
تتبع تفاعل المستخدمين مع إشعارات SMS وقياس فعالية الاتصالات.

### المكونات

#### أ. جدول `sms_tracking_links`
```sql
- id: معرف فريد للرابط
- issue_id: معرف الشكوى
- short_code: رمز قصير فريد (8 أحرف)
- full_url: الرابط الكامل للتتبع
- recipient_type: نوع المستقبل (citizen/mp/admin)
- recipient_id: معرف المستقبل
- click_count: عدد النقرات
- first_clicked_at: وقت أول نقرة
- last_clicked_at: وقت آخر نقرة
- ip_address: عنوان IP
- user_agent: معلومات المتصفح
```

#### ب. Edge Function: `create-tracking-link`
**الوظيفة**: إنشاء روابط تتبع فريدة لكل شكوى

**المدخلات**:
```json
{
  "issueId": "uuid",
  "recipientType": "citizen|mp|admin",
  "recipientId": "uuid"
}
```

**المخرجات**:
```json
{
  "success": true,
  "shortCode": "AbCd1234",
  "trackingUrl": "https://sutak.app/track?code=AbCd1234",
  "linkId": "uuid"
}
```

#### ج. Edge Function: `track-sms-click`
**الوظيفة**: تسجيل النقرات وتحديث الإحصائيات

**العمليات**:
1. التحقق من صحة الرمز القصير
2. تحديث عدد النقرات
3. تسجيل وقت أول نقرة
4. تسجيل معلومات المتصفح والـ IP
5. إضافة سجل تدقيق
6. إعادة التوجيه لصفحة الشكوى

### الفوائد
- قياس تفاعل المستخدمين
- تحديد الشكاوى التي تحتاج متابعة
- تحليل فعالية الإشعارات
- تحسين استراتيجية التواصل

## 2. نظام التنبيهات العاجلة (Urgent Alerts System)

### الهدف
اكتشاف الشكاوى العاجلة تلقائياً وإرسال تنبيهات فورية للنواب والإدارة.

### المكونات

#### أ. جدول `urgent_issue_alerts`
```sql
- id: معرف فريد للتنبيه
- issue_id: معرف الشكوى
- urgency_level: مستوى الأولوية (critical/high/medium)
- urgency_keywords: الكلمات المفتاحية المكتشفة
- detected_at: وقت الاكتشاف
- notified_mps: قائمة النواب المخطرين
- notified_admins: قائمة الإداريين المخطرين
- last_notification_at: آخر وقت إخطار
- resolved_at: وقت الحل
```

#### ب. الكلمات المفتاحية المكتشفة

**حرجة (Critical)**:
- قتل، اغتصاب، عنف مسلح، كارثة، حريق

**عالية (High)**:
- عنف، تهديد، حادث، طوارئ

**متوسطة (Medium)**:
- مشكلة خطيرة، حالة حرجة، عاجل

#### ج. Edge Function: `send-urgent-alert`
**الوظيفة**: إرسال تنبيهات عاجلة عبر SMS والبريد

**المدخلات**:
```json
{
  "issueId": "uuid",
  "title": "عنوان الشكوى",
  "description": "وصف الشكوى",
  "urgencyLevel": "critical|high|medium",
  "assignedMpId": "uuid"
}
```

**العمليات**:
1. اكتشاف الكلمات المفتاحية
2. تحديد مستوى الأولوية
3. إنشاء سجل التنبيه
4. الحصول على قائمة النواب والإداريين
5. إرسال SMS لكل مستقبل
6. تسجيل الإشعارات المرسلة

**المخرجات**:
```json
{
  "success": true,
  "alertId": "uuid",
  "notifiedMps": 5,
  "notifiedAdmins": 2
}
```

### الفوائد
- استجابة فورية للحالات الحرجة
- تقليل وقت التدخل
- ضمان عدم تجاهل الحالات الخطيرة
- تحسين الأمان العام

## 3. نظام سجلات التدقيق (Audit Logs System)

### الهدف
تسجيل جميع الأنشطة في النظام لضمان الشفافية والمساءلة.

### المكونات

#### أ. جدول `audit_logs`
```sql
- id: معرف فريد للسجل
- user_id: معرف المستخدم
- action: نوع الإجراء (create/update/delete/login)
- entity_type: نوع الكيان (issue/profile/mp_approval)
- entity_id: معرف الكيان
- old_values: القيم القديمة (JSON)
- new_values: القيم الجديدة (JSON)
- ip_address: عنوان IP
- user_agent: معلومات المتصفح
- status: حالة الإجراء (success/failure)
- error_message: رسالة الخطأ إن وجدت
- created_at: وقت الإجراء
```

#### ب. الإجراءات المسجلة
- **create**: إنشاء شكوى جديدة
- **update**: تحديث حالة الشكوى أو تعيين نائب
- **delete**: حذف شكوى
- **login**: تسجيل دخول المستخدم
- **sms_link_clicked**: نقر على رابط SMS
- **mp_approved**: موافقة إدارية على نائب

#### ج. الدوال المساعدة

**Function: `log_audit_event`**
```sql
log_audit_event(
  p_user_id UUID,
  p_action TEXT,
  p_entity_type TEXT,
  p_entity_id UUID,
  p_old_values JSONB,
  p_new_values JSONB,
  p_status TEXT,
  p_error_message TEXT
) RETURNS UUID
```

### الفوائد
- تتبع كامل للأنشطة
- الكشف عن السلوكيات المريبة
- توفير أدلة في حالة النزاعات
- تحسين الأمان والامتثال

## 4. نظام إشعارات SMS المتقدم (Advanced SMS Notifications)

### الهدف
إرسال إشعارات SMS ذكية ومخصصة مع تتبع الحالة.

### المكونات

#### أ. جدول `sms_notifications`
```sql
- id: معرف فريد
- issue_id: معرف الشكوى
- recipient_phone: رقم الهاتف
- message_body: نص الرسالة
- message_type: نوع الرسالة (issue_created/status_update/urgent_alert/resolution_notice)
- twilio_sid: معرف Twilio
- status: حالة الإرسال (queued/sent/failed/delivered)
- tracking_link_id: معرف رابط التتبع
- sent_at: وقت الإرسال
- delivered_at: وقت الاستقبال
- error_message: رسالة الخطأ
```

#### ب. أنواع الرسائل

**1. إنشاء شكوى (issue_created)**
```
تم استقبال شكوتك برقم #12345
الموضوع: [العنوان]
تابع: https://sutak.app/t/AbCd1234
```

**2. تحديث الحالة (status_update)**
```
تحديث على شكوتك #12345
الحالة الجديدة: قيد المعالجة
النائب المسؤول: [الاسم]
```

**3. تنبيه عاجل (urgent_alert)**
```
🚨 تنبيه عاجل من صوتك
الموضوع: [العنوان]
الأولوية: حرجة
تابع: https://sutak.app/t/AbCd1234
```

**4. إشعار الحل (resolution_notice)**
```
✅ تم حل شكوتك #12345
الحل: [ملخص الحل]
شكراً لاستخدام صوتك
```

## 7. الأمان والخصوصية

### سياسات الوصول (RLS)

**SMS Tracking Links**:
- الإداريون: يرون جميع الروابط
- المستخدمون: يرون روابطهم الخاصة
- النواب: يرون روابط شكاواهم المعينة

**Urgent Alerts**:
- الإداريون: يرون جميع التنبيهات
- النواب: يرون تنبيهات شكاواهم
- المواطنون: يرون تنبيهات شكاواهم

**Audit Logs**:
- الإداريون: يرون جميع السجلات
- المستخدمون: يرون سجلاتهم الخاصة
